# プロジェクト指示ファイル生成タスク (init)

あなたはこのリポジトリを調査し、**今後このリポジトリで作業するAIコーディングエージェント全般**に渡す
指示ファイルを作成する。

## 出力先（厳守）

- 書き込むファイルは **`AGENTS.md`（リポジトリルート）のみ**。
- `CLAUDE.md` / `CONVENTIONS.md` / `.cursorrules` / `.github/copilot-instructions.md` などを
  **新規作成してはいけない**。既存のものがあっても、内容の取り込み元として読むだけ。
- 特定のツール名（Claude Code、Aider、Cursor 等）に依存した書き方をしない。
  「AIコーディングエージェント」として汎用的に書く。

## 前提となる思想

この指示ファイルは**毎セッションのコンテキストに載る**。したがって簡潔さが最優先。
判断基準は一つだけ:

> 「これが書かれていなかったら、エージェントが間違えるか?」

YES のものだけ書く。NO のものは1行も書かない。

---

## Phase 1: 調査

以下を可能な範囲で読み、事実を集める。推測で埋めない。

**必須**
- `README.md` および `docs/` 配下の主要ドキュメント
- パッケージ / スクリプト定義: `composer.json`, `package.json`, `Makefile`, `pyproject.toml` など
- テスト設定: `phpunit.xml`, `jest.config.*`, `pytest.ini` など
- Lint / 整形 / 静的解析: `.editorconfig`, `pint.json`, `.php-cs-fixer.php`, `phpstan.neon`, `.eslintrc*`
- CI定義: `.github/workflows/*`, `.gitlab-ci.yml`
- 実行環境: `Dockerfile`, `compose.yaml`, `.env.example`
- **既存のAI向け指示ファイル**: `CLAUDE.md`, `.cursor/rules/**`, `.cursorrules`,
  `.github/copilot-instructions.md`, `CONVENTIONS.md`
  → 読んで**重要部分を `AGENTS.md` に統合する**（元ファイルは変更しない）

**構造把握**
- ディレクトリツリー（深さ2〜3）
- エントリポイント、ルーティング定義、主要なドメインロジックの置き場所

---

## Phase 2: 分析

単一ファイルを見るだけでは分からない、**複数ファイルを読んで初めて分かること**を抽出する。

- アーキテクチャの大枠（レイヤ構成、責務の分け方、データの流れ、依存の方向）
- このリポジトリ固有のルール
  - 独自の命名規則・ディレクトリ規約
  - フレームワーク標準から意図的に外している箇所
  - 触ってはいけない / 自動生成されるファイル
- 実際に使われているコマンド（CI や README に根拠があるものだけ）

---

## Phase 3: 出力

`AGENTS.md` を以下の構成で作成する。
**該当する情報がないセクションは、セクションごと省略する**（見出しだけ残さない）。

```markdown
# AGENTS.md

このファイルは、このリポジトリで作業するAIコーディングエージェントへの指示です。

## プロジェクト概要
（2〜4行。何をするシステムか、技術スタック）

## よく使うコマンド
- 依存インストール:
- 開発サーバ起動:
- テスト全体:
- テスト単体（1ファイル / 1メソッド）:   ← 必ず入れる
- Lint / 整形:
- 静的解析:
- マイグレーション:

## アーキテクチャ
（複数ファイルを読まないと分からない「大きな絵」。
  ディレクトリの羅列ではなく、責務と依存の方向を書く）

## このリポジトリ固有のルール
（標準から外れている点、ハマりどころ、禁止事項）

## 注意
（触ってはいけないファイル、生成物、機密情報の扱い）
```

---

## 禁止事項

- 一般論を書かない（「読みやすいコードを」「適切なエラーハンドリングを」等）
- `ls` や grep ですぐ分かることを列挙しない（全ファイル一覧、全コンポーネント一覧）
- 実在を確認していないコマンド・手順を書かない
- 「開発のヒント」「サポート情報」など、リポジトリ内に根拠のないセクションを創作しない
- 同じことを別セクションで繰り返さない
- 分量の目安: 100行以内。超えるなら削る。

## 既存の `AGENTS.md` がある場合

上書きせず、**差分の改善提案として提示**し、承認を得てから反映する。
古くなった記述（存在しないモジュール、廃止されたコマンド）の削除も提案に含める。
